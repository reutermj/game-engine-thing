# Reviews

Dated design and consistency reviews of the whole repo: where the docs and
the code have drifted apart, where one idea is done two ways, and what has
grown awkward enough to need a decision. Each one is named
`<date>-<topic>.md`. Like a retrospective, a review isn't updated afterward.
Its findings are acted on through the beads it lists, and the fixes land
in `docs/architecture/` and the code.

They live here, not in `docs/architecture/`, because they are a snapshot of
many areas at once, not the design of one. They aren't retrospectives
either, which record what one piece of work showed.
